# 原子需求完整规格模板

> **目的**: 确保每个原子需求都包含足够的结构信息，可直接交付和自动验证。
> **版本**: 1.0

---

## 模板结构（10 章节）

每个原子需求文档必须包含以下 10 个 `##` 二级章节。章节不能省略；如某章节不适用于当前需求，必须在对应章节内明确标注「不适用」并说明非空原因。

### 1. 目标
> 一句话说明唯一业务结果。

### 2. 影响服务
> 列出主责服务、共享契约以及明确不修改的服务。

### 3. 输入契约
> 给出 API/protobuf/event 字段、校验、大小限制和幂等键。

### 4. 输出契约
> 给出成功响应、事件、持久化结果和稳定错误码。

### 5. 状态与数据
> 定义状态转换、表字段、唯一约束、事务边界和迁移兼容。

### 6. 错误模型
> 覆盖校验、冲突、权限、依赖失败、超时、取消和重试语义。

### 7. 安全边界
> 定义身份、授权、敏感数据、凭据与日志规则。

### 8. 验收标准
> 每条必须是 Markdown 复选列表项，使用 `AC-XXX-NN` 编号并包含 Given/When/Then；结果必须可由输入、输出、状态或稳定错误自动判定，不得要求人工检查、确认或解释内部实现。
> 格式：
> ```markdown
> - [ ] AC-XXX-01 Given X，When Y，Then Z。
> ```

### 9. 非目标
> 列出容易被顺手加入但必须留给其他需求的内容。

### 10. 回滚方式
> 说明代码回滚、数据库兼容、运行中状态和数据保留策略。

## 验证规则

使用 `reqcheck` 工具对需求文档进行自动验证：

```bash
make check-reqs
# 或
go run ./cmd/reqcheck/ docs/*.md
```

### 检查项

| 检查 | 规则 |
|------|------|
| CHK-01 | 十章节标题均存在（`## 目标`, `## 影响服务`, `## 输入契约`, `## 输出契约`, `## 状态与数据`, `## 错误模型`, `## 安全边界`, `## 验收标准`, `## 非目标`, `## 回滚方式`） |
| CHK-02 | 「不适用」只能写在对应章节内，且必须附非空原因 |
| CHK-03 | 验收标准必须是复选列表中的 `AC-XXX-NN` 条目，并含 Given/When/Then |
| CHK-04 | 验收结果不得依赖人工检查、确认或解释内部实现 |

### 标记「不适用」

```
## 状态与数据
不适用 — 本需求为纯配置变更，不涉及数据库或状态机。
```
